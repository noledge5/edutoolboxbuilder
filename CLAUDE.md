# Arbeitsblatt-Baukasten

Browser tool for a German Realschule teacher to build printable A4 worksheets from blocks. Vite + React + TypeScript, no backend, deployed to GitHub Pages.

## Read first
- `docs/design/README.md`: the design spec (layout, colours, every block type, interactions). The prototype `docs/design/Arbeitsblatt-Baukasten.dc.html` (its `<script data-dc-script>` logic class) is the functional spec.
- `docs/roadmap.md`: decisions made with the user and the phase plan. Stay within the current phase unless asked.

## Structure
- `src/App.tsx` loads the library and routes by URL hash (`src/library/router.ts`): overview `#/?fach=…&klasse=…`, module `#/modul/<id>`, lesson editor `#/stunde/<id>`, slides `#/folien/<id>`, year plan `#/jahresplan?fach=…&klasse=…`.
- Library model (`src/library/`): subjects and grades hold modules; a module holds lessons (each one worksheet `Doc` plus `slides`, a planning note `plan`, a `role` in the unit and the `competences` it works on; roles in `planning.ts`) and a competence grid (G/M/E). Packages carry `role` and `competences` per lesson; `addPackage` maps competence ids into a grid that stays (`gridIds`). A lesson's icon and code (`K9 · M1 · S2`) always come from its module (`docForLesson`). A lesson whose pages have no blocks is only planned (`isWorkedOut`) and shows pale.
- Storage (`src/storage/library.ts`): IndexedDB entries `modul:<id>`, `stunde:<id>`, `lib:einstellungen`, `lib:geloescht` (tombstones), `lib:abgleich`, `lib:ablage` (the Ablage), images `img:<id>`. Backup files (`src/storage/backup.ts`) carry images as data URLs.
- Mac ↔ iPad sync (`syncLibrary` in `src/library/model.ts`, `SyncDialog.tsx`): newest `updatedAt` wins per module and lesson, deletions travel as tombstones. Every change to a module or lesson must set `updatedAt`.
- Stundenpaket (`src/library/package.ts`): modules with competences and lessons (planned lessons without pages, slides), the format Claude writes. `readPackage` repairs and returns German notes; `addPackage` completes a module with the same number when nothing worked out is overwritten, else makes a new module. Year plans as text: `src/library/plantext.ts`.
- Instructions for Claude (`src/claude/`): `anleitung.md` plus generated block reference, icon list and example. After changing blocks, fields or icons run `npm run anleitung` to update `docs/claude/anleitung-fuer-claude.md` (a test fails otherwise).
- Sheet modes (`src/sheet/sheetMode.ts`): answers hidden (student sheet), ghost (editing) or shown (solution sheet); `bw` for the black-and-white copy master. Teacher pages (`type: 'lehrkraft'`) have no page number and print only with the solution sheet.
- PWA: `public/manifest.webmanifest`, `public/sw.js` (registered in production only).
- Slides (`src/model/slides.ts`, `src/slides/`): 1920 × 1080 layouts after `docs/design/referenz/Präsentation Treibhauseffekt.dc.html`, colours from `THEMES`; `slides.css` is a design layer like `sheet.css`. Slide images count for backups and clean-up (`slideImages`). `suggestSlides` (`src/slides/fromDoc.ts`) suggests slides along the lesson plan (block `plan`): recall from earlier lessons (`earlierLessons`, `recallQuestions`), the beginning after block `hook`, per work phase a `work` slide and the phase's tasks as `task` slides with their solutions (gaps `[[…]]` fill in), the Merksatz at the end; `SuggestDialog` shows them as a list to tick. New task blocks need a case in `taskBody` there. Designs per lesson (`slideDesign`, `SLIDE_DESIGNS`) are CSS classes `is-d-<design>` in `slides.css`. Texts on the slide are edited in place through `data-edit` targets (`editText`/`setEditText`, `SlideStage`). PowerPoint: `src/slides/pptx.ts` draws the slides off screen and turns boxes, text and pictures into shapes (clicks become entrance animations, the original slides ride along in `baukasten/folien.json`); `pptxImport.ts` reads .pptx back. Presenting (`Presenter.tsx`): tools in `tools.ts` (timer, Ampel, black/white screen; pure, tested), their buttons and overlays in `PresentTools.tsx`, the gong in `gong.ts` (Web Audio). The Referentenansicht (`speaker.ts`) opens a second window and renders into it through a portal (`preparePopup` copies the styles); Chrome's Window Management API puts the audience full screen on the projector, otherwise the new window holds the slides. While presenting, answers that come on a click lie under cards (`Slide.cards`, `.sl-card`) that can be tapped open one by one (`opened` keys; `nextStep` skips clicks with nothing new); element kind `cover` goes on its click or when tapped. The pen (`Pen.tsx`: settings, `useInkInput`, `PenBar`; strokes in `src/model/ink.ts`, drawn with perfect-freehand in `Ink.tsx`) writes on slides and blank boards (`deckOrder`); what was written can be kept as a Tafelbild (`Lesson.boards`, `BoardsDialog`, printed by `SlidesPrint` kind `board`). Sketches drawn in the editor are elements of kind `ink`. Layout `work` (Arbeitsauftrag) has steps (`workSteps`) whose timers start by themselves.
- Page field `back`: the back of the page before it, slim header with the front's title (`frontOf`).
- Subject colours (`src/library/subjectColor.ts`): the app's `--color-accent*` follow the subject; `.ws-page` and `.sl-slide` reset them to the orange ramp `--color-accent-1-*`.
- Image search (`src/storage/imageSearch.ts`): Openverse and Wikimedia Commons without a key; Wikimedia thumbnails only in its standard widths (330, 1280 …).
- Safety net (this device only, not in backups): trash `lib:papierkorb` (`toTrash`, `restoreFromTrash`, `TRASH_DAYS`), earlier versions per lesson `fassung:<id>` (`addVersion`, `keepVersion`; kept in `putLesson` at most every 30 minutes and before sync, import, new slides). Image clean-up counts trash and versions.
- Print variants (`src/model/variants.ts`): only some levels (G/M/E) and test group B (answers and entries shuffled with a seed, solutions follow); the editor's preview renders `variantDoc`, the group shows through `SheetMode.group`.
- Search (`src/library/search.ts`, `SearchDialog.tsx`): ⌘K or `SearchButton` (through `SearchContext` from `App`) in every top bar. The index holds modules, lessons, block texts (`blockText`: fields of kind text/area/ipa, plus the block's label) and slide texts; hits in the subject and grade in view come first. A hit jumps through `Jump` in `App` to the `focus` prop of `Editor`/`SlidesView`; `markFound` (`highlight.ts`) marks the words with the CSS Custom Highlight API. Lessons opened last: `recent.ts` (localStorage). Toolbox search: `src/editor/blockSearch.ts` (`BLOCK_WORDS`).
- Several blocks and the Ablage: `Selection` kind `blocks` (⌘/⇧-click, `pickBlock`, the picking mode for the iPad, the `multi-bar`), with `blocksOf`, `deleteBlocks`, `copyBlocks`, `insertBlocks` in `ops.ts`. The Ablage (`src/model/clips.ts`, device only, the last `MAX_CLIPS`) shows in the toolbox; ⌘C/⌘X/⌘V, drag item kind `clip`. Its images count for the clean-up.
- Handing out digitally (`src/share/`, student view `src/student/`, page `a/index.html` → `…/a/#<id>`): `handoutPages` picks blocks, `taskSlots`/`isRight`/`gradeTask` (`grade.ts`) turn task blocks into answerable slots and grade them, `stripSolutions` makes the test copy. An `Assignment` is published to GitHub (`github.ts`, Git Data API, repo `noledge5/baukasten-aufgaben`, token per device in `geraet:github`); the teacher keeps a `Handout` (pages with solutions, private key) in `Library.handouts`, synced like lessons. Students' work is sealed with the handout's public key (`crypto.ts`) and sent to Supabase (`server.ts`: functions `einreichen`, `ergebnisse_holen`; deleted after 14 days); `EvaluationView` (`#/auswertung/<id>`) opens it and `evaluate.ts` aggregates. New task blocks need a case in `taskSlots`, `stripSolutions` and the student `Body` (`src/student/Tasks.tsx`).
- KI im Baukasten (`src/ai/`): key, models, monthly spend per device in IndexedDB `geraet:ki` (`settings.ts`, never in backups or sync), requests through the Anthropic SDK in the browser or OpenRouter (`client.ts`, streamed, `claudeInstructions()` as the cached system prompt, cost from `prices.ts`), `runAi` asks before going over the limit. `context.ts` places a lesson in the year plan (week, holidays, competences, lessons before and after); `lesson.ts` asks for a Stundenpaket with that one lesson and reads it back keeping the module's competence ids (`LessonAiDialog` in the editor); `yearplan.ts` plans modules with planned lessons (`YearPlanAiDialog`, applied like an import); `helpers.ts` rewrites one block (only text fields; `BlockAiDialog` from the panel). `moduleplan.ts` (`ModulePlanAiDialog`, from the module view) plans a unit from its end: grid and planned lessons with role and competences; `applyModulePlan` keeps worked-out lessons and the grid of a module in progress, replaced planned lessons go to the trash. Class profile per subject and grade and the teacher's principles (`Settings.classProfiles`/`principles`, `classNotes.ts`, `ClassNotesDialog`/`ClassNotesLine` through `ClassNotesContext` from `App`) go into every context (lesson, year plan, module, task). The didactic guidelines live in `anleitung.md` („Didaktische Leitlinien“, „Fachdidaktik“, „Ein Modul planen“); requests without the whole Anleitung get `DIDACTICS_BRIEF`. `task.ts` (`TaskAiDialog`, panel „Mit Anweisung neu machen …“ and the editor's Claude menu) turns the teacher's own instruction into 1–3 blocks of any type (`blocksFromAnswer`: competence and level kept, only the old block's images) that replace the block (`ops.replaceBlock`) or go after it (`api.insertAfter`). Pictures with AI (`images.ts`, `ImageAiPane.tsx`, a tab of `ImageSearchDialog`): OpenRouter image models (`modalities: ['image','text']`, `image_config.aspect_ratio`, the picture comes as a data URL in `message.images`), key `imageKey` beside a Claude key or the OpenRouter key itself (`imageKeyOf`); style presets per age (`AiGradeContext` from `App`); image and hook blocks carry `describe` (Claude's picture description, prefilled). Every dialog also has the chat way (`ChatPath` in `parts.tsx`). `vocab.ts` (`VocabAiDialog`, from the editor's Claude menu and the module's Vokabeln menu) lists the new words of a lesson or unit (known: `gradeVocab`) in word fields and makes Vocabulary pages: one `vocab` block per field (props `picwords`/`pics` give the picture column) and a `wordweb`.
- Subject designs (Fachdesigns, `src/model/look.ts`, CSS `src/sheet/fachdesigns.css`, handoff in `docs/design/fachdesigns/`): `Module.look` (absent: the subject decides, `fachOf`; the grade gives the age group) → `Doc.look` via `docForLesson` and `SlideContext.look` (used when the slide design is "organisch"). With a look the page/slide root gets `lookClasses` + `typeClass` and no inline sheet-type colours; box variants become `is-v-*` (`variantProps`), flow steps `is-c1…4`. Geometry must not change: no `border`, only inset shadows. PowerPoint rasters elements with `data-om-raster` (`rasterDecor` in `pptx.ts`).
- Readers for stored and imported library data: `src/library/read.ts` (defaults for fields added later). Year plan maths: `src/library/yearplan.ts`. Vocabulary, points, grade scale, tips: `src/model/language.ts`.

## Rules
- UI text is German and follows the labels in the design spec exactly. Code, identifiers and comments are English.
- Two visual layers: `src/sheet/` is the printed page (Caprasimo headings, Figtree body) and must stay pixel-accurate to the spec. The editor chrome (`src/editor/`, `src/styles/app.css`) uses the Helvetica Neue UI font, never Caprasimo.
- Design tokens live in `src/styles/tokens.css`, copied from `docs/design/tokens/organic-styles.css`. Use the CSS variables, not raw hex values.
- The document (`Doc` in `src/model/types.ts`) is also the JSON import/export format. Any change to it must keep `normalizeDoc` in `src/model/normalize.ts` accepting older data.
- Document changes go through the pure functions in `src/model/ops.ts` (immer), so undo/redo keeps working.
- Topic icons for the header band are a curated list in `src/topicIcons.ts` (German labels and search words); add new ones there, not by importing all of Lucide.
- New block type: add it to `BLOCK_TYPES` (`src/model/blockTypes.ts`), render it in `src/sheet/BlockContent.tsx` (language, test and whole-sheet blocks in `src/sheet/LanguageBlocks.tsx`, listed in `LANGUAGE_BLOCKS`) with styles in `src/sheet/sheet.css`, give it an icon in `src/icons.tsx`, a line in `BLOCK_USE` (`src/claude/instructions.ts`) and search words in `BLOCK_WORDS` (`src/editor/blockSearch.ts`); a task also needs its digital form (`taskSlots`, `stripSolutions`, student `Body`); then run `npm run anleitung`. Tasks get the common task fields through `taskFields()`.
- Sheet language: the worksheet's `lang` comes from the module. Fixed texts on the sheet go through `SHEET_TEXT` (`src/sheet/lang.ts`), quotation marks through `typo()`. Teacher pages stay German.
- Colours beyond the design handoff: the ramps `--color-accent-3` … `--color-accent-7` in `tokens.css` (sheet types, box variants, toolbox groups).
- Everything must work with touch on an iPad (dnd-kit TouchSensor, long-press to drag) and in print (`src/styles/print.css`: one A4 page per sheet).

## Commands
- `npm run dev`, `npm run typecheck`, `npm test`, `npm run build`
- Visual check: build, run `npx vite preview`, and drive it with Playwright (Chromium at `/opt/pw-browsers` in the cloud environment). Check print output with `page.pdf({ preferCSSPageSize: true, printBackground: true })`.
